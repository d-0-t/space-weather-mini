# Horizon 1 — Aurora Now Dashboard on Home (Kp live, NOAA Scales, Bz banner, ultracompact 3-day, alerts v1, where-am-I)

Status: ready-for-agent

## Problem Statement

Aurora chasers using the current app see NOAA text products (forecast discussion, 3-day forecast, weekly report, 27-day outlook, daily geomagnetic indices, geophysical alert per `CONTEXT.md:9`) plus a static OVATION `latest.jpg` pair on `Home.tsx:19`. The app tells them what NOAA wrote, but not *is it happening now where I am* — live planetary K-index, NOAA G/R/S scale, southward Bz (GSM) and solar wind, hemispheric power and Dst all update every 1–60 minutes and are already CORS-open on `services.swpc.noaa.gov` (`Access-Control-Allow-Origin: *`, `max-age=60` verified 2026-08-25 per `docs/research/aurora-chaser-features-2026-08-25.md:34`), yet the app only fetches on mount and shows no live banner. The daily geomagnetic indices table is 30 days of history; the 3-day forecast page is a full table-plus-rationale that overwhelms Home. There is no threshold alert ("tell me when Kp ≥5") and no "how far to the oval?" distance. Field use is hampered by requiring manual reload to see a Bz south flip that precedes aurora by 20–40 minutes.

## Solution

Make `Home` (`src/components/pages/Home.tsx:7`) the chaser **Now dashboard** while keeping the six text products intact under `Details` (renamed nav trigger, routes `src/components/App.tsx:19` stay `/forecasts/*`). Home becomes:

`[Scales Now pill] → [Kp live dashboard] → [Live solar-wind / IMF banner (Bz GSM · Bt · speed · density · hemispheric power GW · Dst)] → VisualAuroras latest.jpg pair → Ultracompact 3-day Kp min/max table + full-page link → (1b) In-app alerts banner driven by Kp threshold in `localStorage` → (1b) "Where am I vs oval?" distance pill (single-shot Geolocation)`

All live data polls per `docs/adr/0003-live-polling-for-real-time-products.md:8` (text stays fetch-on-mount). Every live card shows `As of {issuedUTC} · Updated {age}` plus stale-cache fallback. Thresholds persist as `localStorage["sw:thresholds:v1"] {kp:5}`. Delivered in two tranches: **1a** = Kp + Scales + banner (no permissions), **1b** = alerts + where-am-I (permissions, still no backend).

## User Stories

1. As an aurora chaser, I want Home to show a live planetary K-index dashboard (current value, observed history 8 days/3h and forecast 3 days/3h with G label when Kp ≥5 per `CONTEXT.md:67`), so that I can decide to go out without opening the 30-day table.
2. As a chaser, I want the NOAA scale pill row on Home (current `G:{Scale,Text}` and Day-1–3 G/R/S probs from `products/noaa-scales.json:49`) in 1.1 KB, so that I see the official storm level in one glance.
3. As a chaser, I want the live banner on Home to show Bz (GSM) (`CONTEXT.md:92` southward = aurora enable), Bt, solar wind speed, particle density, hemispheric power GW (`CONTEXT.md:94`) and Dst index (`CONTEXT.md:78`), each as a pill with `As of` age, so that I see the drivers together.
4. As a chaser, I want an expandable detail under the banner with 6-hour sparklines (Bz/Bt/speed/density, Dst, hemispheric power) as Recharts lines paired with a hidden table, so that I can spot a southward flip and substorm main phase.
5. As a chaser, I want Home to keep the OVATION aurora images (`VisualAuroras.jsx:10` `latest.jpg` N+S) between the live strips and the forecast, so that the oval context stays.
6. As a chaser, I want an ultracompact Kp-index forecast table on Home (`Kp-index forecast | Min | Max` per day, min/max of the day's 8 Kp values from `src/products/3-day-forecast.ts:62`, with G bonus label when max ≥5), plus a link "Full 3-day →", so that Home stays scannable while the full prose stays under Details.
7. As a chaser, I want the daily geomagnetic indices big table to remain under Details (`/forecasts/daily` via `src/products/daily-geomagnetic-indices.ts:21`), even though Kp live is now canonical on Home, so that 30-day history is not lost.
8. As a visitor, I want the nav disclosure `Nav.tsx:56` trigger renamed from "Forecasts & Discussion" to "Details" (routes stay `/forecasts/*` with optional `/archive` alias), so that live Now on Home vs textual details is clear.
9. As a visitor, I want the Home intro `Home.tsx:11` to explain "Live now on Home — full reports in Details", so that wayfinding survives the nav rename.
10. As a chaser, I want to set a Kp alert threshold (slider 1–9, default 5 = G1, stored in `localStorage["sw:thresholds:v1"]`), so that future alerts respect my latitude.
11. As a chaser, I want an in-app alerts banner on Home that polls `products/alerts.json:50` (5 min) plus `noaa-scales.json:49` and the next-24h forecast, filtered `kp ≥ threshold` or `G ≥ threshold`, deduped by `product_id+issue_datetime`, so that I see threshold breaches while the tab is open.
12. As a chaser, I want the alerts banner to show even without browser Notification permission, so that foreground alerts work before I opt into system notifications.
13. As a chaser, I want an explicit "Enable browser alerts" button that calls `Notification.requestPermission()` on tap (iOS 16.4+ Home Screen caveat noted per `docs/research/aurora-chaser-features-2026-08-25.md:126`), so that I can get `showNotification()` when Home is open.
14. As a chaser, I want a "Where am I vs oval?" pill — single-shot `getCurrentPosition({enableHighAccuracy:true, timeout:8000, maximumAge:60000})` → haversine distance + `coords.accuracy` (e.g. "Aurora 240 km N · ±30 m") with manual lat/lon fallback — so that I know distance without persisting location.
15. As a privacy-minded chaser, I want Geolocation single-shot and not persisted (no `localStorage` lat/lon unless I later opt into "Remember"), so that my position never leaves the device.
16. As a chaser on the hill with flaky signal, I want each live card to keep its last cached value and show `⚠ Live data unavailable — showing 6m-old cache` with `aria-live="polite"` when `services.swpc.noaa.gov` fails, while text products show a plain error (existing `coding-standards.md:22`), so that I am not blind.
17. As a chaser, I want every live card to show `As of {issuedUTC} · Updated {X ago}` (live age per `docs/adr/0003:8`) plus the UTC/local issued pair and author line already required by ADR-0001, so that freshness is explicit.
18. As a keyboard/screen-reader user, I want each Recharts line (Kp history, Bz, Dst, etc.) paired with the same-data table (table is source of truth per `docs/agents/coding-standards.md:26`), `role="img"` + `aria-label` listing every series, distinct `legendType` shape plus color (no color-only encoding), and focus on the banner controls visible in `--color-accent` Light Lime (`docs/adr/0002:3`), so that WCAG 2.1 AA holds.
19. As a developer, I want each new live feed modelled as a pure `string → Product` parser (JSON validated, not `any`), typed rows mirroring `src/products/3-day-forecast.ts:26` and `daily-geomagnetic-indices.ts:14` precedent, so that data is testable and chartable.
20. As a developer, I want TanStack Query keys per URL with `live:true` flag, `refetchInterval` per product (summary 60s, Kp/Scales/alerts/Dst/hemispheric power 5 min), `refetchIntervalInBackground:false`, staleTime matching `Cache-Control: max-age=60`, so that the data layer remains the single swap point if a backend is added later (`docs/adr/0001:13`).

## Implementation Decisions

- **Tranches (grill Q1 B):** `1a` = Kp live + NOAA Scales + live banner (no permissions, validates `docs/adr/0003`). `1b` = alerts v1 + where-am-I distance pill (permissions). PWA minimal is **deferred** to Horizon 2 per Q12 B — no Service Worker/manifest in this spec.
- **Home composition (Q2 B + Q7):** `src/components/pages/Home.tsx:7` becomes vertical flow: `Scales Now pill → Kp live dashboard → Live banner (collapsed) → VisualAuroras → Ultracompact Kp min/max table (3 rows: day name, Min Kp, Max Kp, G bonus pill when max ≥5, link to full `/forecasts/3days`) → (1b) Alerts banner → (1b) Where-am-I pill`. `VisualAuroras` (`Auroras.jsx:3`) stays as the oval anchor. Full 3-day prose and probability tables remain only on `forecasts/3-day-forecast.tsx:88`.
- **Nav rename (Q8 Details):** `src/components/navigation/Nav.tsx:13` trigger label `Forecasts & Discussion` → `Details` (`Nav.scss` styles unchanged). Routes in `src/components/App.tsx:19` stay `/forecasts/*` (no breaking change); optional alias `/archive/*` is a follow-on, not required for Horizon 1. Home intro copy `Home.tsx:11` updated to wayfind.
- **Kp source of truth (Q3):** `noaa-planetary-k-index.json:45` + `…-forecast.json:46` are canonical for Now. `daily-geomagnetic-indices.ts:21` big table remains public at `/forecasts/daily` — no parser change, just de-emphasised via nav. Terminology: `CONTEXT.md:52` **Kp index** is the measure; `CONTEXT.md:78` **Dst index** and `CONTEXT.md:52`+ `Planetary K-index (live)` vs `CONTEXT.md:29` **Daily geomagnetic indices** product are disambiguated (already added via grill-with-docs).
- **Scales pill:** `products/noaa-scales.json:49` single `fetch` in `1a`, `noaa-scales.ts` parser `string → {current:{R,S,G}, day1:{}, day2:{}, day3:{}, yesterday:{}}` with `issued` passthrough for `As of`. Pill row uses `-`—`G5` badge classes derived from frozen `.kp01–.kp9` mapping per `docs/adr/0002:3` (no new data colors).
- **Live banner (Q10 A):** `1a` banner assembles from tiny endpoints that are always `<15 KB` combined: `products/summary/solar-wind-mag-field.json:51` (`{bt,bz_gsm,time_tag}`), `products/summary/solar-wind-speed.json:51`, density via `products/summary/*` or stub from `rtsw_wind_1m.json:52` trimmed server-side? No server — use `rtsw_wind_1m.json` only for the expand detail (windowed to 6h, ~360 points). `text/aurora-nowcast-hemi-power.txt:43` (11 KB) parsed as `string → {powerGW, minuteTag}` (first line after `#` comment, ignore blank). `products/kyoto-dst.json:54` parsed as `string → {points:{time_tag,dst}[]}`. Banner pills show numeric value + unit + `As of hh:mm UTC`. Expand sheet: Recharts `LineChart` 6h sparklines (Bz, Bt, speed, density, Dst, HPI) each paired with a `sr-only` table.
- **Polling (Q5 + ADR 0003):** `useQuery({ queryKey:["noaa-scales","live"], queryFn:fetchScales, refetchInterval: 5*60*1000, refetchIntervalInBackground:false, staleTime:60*1000 })` for Kp/Scales/alerts/Dst/HPI; `60*1000` for `summary/solar-wind-*`. `refetchIntervalInBackground:false` preserves battery; hidden-tab tests assert pause. All live queries respect `gcTime` 10 min so stale cache can render with `⚠`. Text product queries (`THREE_DAY_FORECAST_URL:35`, `DAILY_GEOMAGNETIC_INDICES_URL:21`, etc.) stay fetch-on-mount only.
- **Local freshness display (Q11):** Every live card renders `Issued (UTC): {issued} • Issued (local): {formatIssuedLocal(issued)} • Updated {age}` where `age` is `Date.now()-time_tag` formatted `just now / 2m ago / 1h 5m ago`. Author line shown where available. Error branch: `isError && data` keeps last cache and injects `⚠ Live data unavailable — showing {age}-old cache` inside `aria-live="polite"`; `isError && !data` shows `Couldn't load … Please check back later.` per `forecasts/3-day-forecast.tsx:101` precedent.
- **Ultracompact Kp table derivation:** From `parseThreeDayForecast`'s `kpBreakdown: KpBreakdownRow[]:3` (8 rows `00-03UT` … `21-24UT`, each `days:number[3]`): per day i, `min = Math.min(...kpBreakdown.map(r=>r.days[i]))`, `max = Math.max(...same)`, formatted via `kpClass(kp)` token and `Kp` string (`Kp1+` style — preserve NOAA `Kp2-` etc. as strings if API returns string, else numeric `Kp4`). G bonus: `if(max>=5) badge G{max-4}` per `CONTEXT.md:67`. Link `→ Full 3-day forecast` goes to `/forecasts/3days`.
- **Alerts v1 (Q9):** Threshold control: single range/select `Kp 1–9`, default `5`, stored `localStorage["sw:thresholds:v1"] = JSON.stringify({kp:5, v:1})` (versioned for migration). Hydrate on mount; persist on change. Filter: `scales.G.Scale >= threshold.g` (`G1=5`) OR any `alerts.json` item where `message` contains `G{threshold-4}` OR any `noaa-planetary-k-index-forecast.json` point in next 24h with `kp >= threshold.kp`. Dedup `alerts.json` by `${product_id}|${issue_datetime}` persisted in `localStorage["sw:alerts:seen:v1"]` set (cap 200). Banner shows up to 3 newest matches as list with `time_tag` + `message` snippet + link to full alerts archive (future). Secondary `Enable browser alerts` button: on tap, `await Notification.requestPermission()`; if `granted`, use `navigator.serviceWorker?.ready.then(r=>r.showNotification(title,{body}))` fallback `new Notification(title)` guarded by `if("Notification" in window)`; catch `TypeError` on iOS and fall back to in-app only. Honest empty: "Alerts while this tab is open. On iOS, add to Home Screen for browser alerts."
- **Where-am-I pill (Q12 minimal):** Button "Where am I vs oval?" → `navigator.geolocation.getCurrentPosition({enableHighAccuracy:true, timeout:8000, maximumAge:60000})`. On success: `lat,lon,accuracy`, `formatDistance` placeholder `Aurora ~{km} km N` — since Horizon 1 defers `ovation_aurora_latest.json:42` grid overlay to Horizon 2, distance is to a Kp-derived latitude threshold (e.g. `viewlineLat = 65 - (kp-5)*2`) as a temporary stub, clearly labelled "approx. (OVATION map in Horizon 2)". On error/deny: show manual two-number inputs `lat, lon` with `Save for this session` (sessionStorage only). On `!navigator.geolocation`: same manual inputs. No `localStorage` persistence unless user checks opt-in (future). Display `±{Math.round(accuracy)} m` warn if accuracy >200 m.
- **Styling:** SCSS + BEM per `docs/agents/coding-standards.md:14`, color tokens only (`--color-*`, `--gradient-card`/`--gradient-header`) for all non-data chrome; frozen `.kp01–.kp9` (`Tables.scss:kp01`) and `td[a-value]` for Kp/A only. Ultracompact table reuses `Tables.scss` zebra `color-mix(in srgb, var(--color-deep-indigo) …, black)`. No new hex.
- **Glossary already updated** via grill-with-docs: `CONTEXT.md:64` **NOAA scale**, **Geomagnetic storm** G1–G5, **Solar wind**, **Interplanetary magnetic field (IMF)**, **Bz (GSM)**, **Hemispheric power**, **Dst index**, **Planetary K-index (live)**. User-facing copy must use those terms (`_Avoid_` lists enforced).
- **ADRs respected:** `0001-client-side-only-architecture.md:3` (no backend, localStorage only), `0002-color-tokens-and-dark-theme.md:3` (dark-only, tokens), `0003-live-polling-for-real-time-products.md:8` (this spec implements it). No new ADR needed for Details rename; nav label is presentation, not architecture.

## Testing Decisions

- **What makes a good test (per `docs/agents/coding-standards.md:39`):** Assert external behavior only — feed raw NOAA fixture JSON/text, assert typed product or rendered landmarks/content, not helpers or component internals. No snapshots of parser output. Axe audit per page via Playwright as already established in `coding-standards.md:36`.
- **Primary seams — ranked highest first:**
  1. **Parser seam `string → Product` (one seam per new feed):** `products/noaa-scales.ts`, `products/noaa-planetary-k-index.ts` (+ forecast), `products/alerts.ts`, `products/summary-solar-wind.ts` (bt/bz/speed), `products/hemi-power.ts`, `products/kyoto-dst.ts`. Each with a fixture file under `src/products/fixtures/` (real SWPC JSON/TXT fetched once, checked in) plus edge fixtures: empty/alerts:none, `Scale:"0"`, `bz_gsm:-2.3`, power `12 GW`, negative Dst `-87`. Vitest unit per `docs/agents/coding-standards.md:39` prior art (`27-day-outlook.test.ts`, `daily-geomagnetic-indices.test.ts:90`, `product-header.test.ts`).
  2. **Home dashboard seam:** `src/components/pages/Home.test.tsx:7` component smoke — renders scales pill, Kp chart/table, live banner pills, ultracompact Kp table with min/max derived from fixture `3-day-forecast.txt`, link to full page, threshold slider writes `localStorage`, alerts banner filters fixture `alerts.json`, where-am-I button renders + fallback inputs when `navigator.geolocation` is undefined. No polling timing asserted — just that `refetchInterval` is set (assert via `queryClient` mock if needed), pause on `document.hidden` is verified via unit of the hook, not e2e.
  3. **Navigation seam:** `src/components/navigation/Nav.test.tsx:13` already covers disclosure + `aria-expanded`/`aria-controls:submenuId:16` + Esc/blur; extend to assert `Details` label, 6 submenu links still present, Home intro copy case.
  4. **Live freshness/error seam:** Unit test for `formatAge(time_tag)` and `formatIssuedLocal:46` pair; component test that `isError && data` shows `⚠` plus cached table (mirroring `forecasts/3-day-forecast.tsx:106` branch), `aria-live="polite"` present.

- **Out of parser seam:** Canvas/Leaflet OVATION overlay, horizon math, cloud/moon tiles — explicitly not in this spec (Horizon 2).

## Out of Scope

- **PWA** — `vite-plugin-pwa` `generateSW`, manifest, precache, `CacheStorage`/`IndexedDB` split, offline shell audit (deferred to Horizon 2 per Q12 B). Home works online-only in Horizon 1; stale `gcTime` cache is the only offline grace.
- **OVATION gridded JSON** — `json/ovation_aurora_latest.json:42` + canvas/WebGL overlay, coordinate decimation, `OffscreenCanvas` worker, `Forecast Time` vs `Observation Time` handling — Horizon 2.
- **Personal horizon / elevation forecast** — haversine + magnetic latitude + `suncalc` solar elevation → "low N horizon / overhead" per location — Horizon 2 (`docs/research/aurora-chaser-features-2026-08-25.md:174`).
- **Cloud + moon + darkness fusion** — Open-Meteo cloud, `suncalc` moon, VIIRS light-pollution tiles, go/no-go score — Horizon 2 (`§175`).
- **24h OVATION timelapse scrubber** (`products/animations/ovation_north_24h.json:44`), Enlil movie — Horizon 2.
- **GOES magnetometers** detailed stackplots beyond the Dst already in banner, GOES X-ray/electron series, WSA-Enlil full time series, solar probabilities — not in Horizon 1.
- **Push API** (`Push_API` + VAPID + endpoint DB) — violates ADR-0001; foreground `Notification` only in Horizon 1.
- **Periodic Background Sync / Background Sync / Background Fetch** — 0% iOS per research §3.1 — not viable.
- **Persisted Geolocation** — no `localStorage` lat/lon in Horizon 1 unless explicit opt-in (future).
- **Any backend, proxy, auth, community photos/webcams aggregation** — violates ADR-0001.
- **Light theme** — dark-only per ADR-0002 (nightside visibility).

## Further Notes

- **Data contracts:** All Horizon 1 live URLs are `https://services.swpc.noaa.gov/*` with `CORS:*` + `Cache-Control: max-age=60` as verified 2026-08-25 (`docs/research/aurora-chaser-features-2026-08-25.md:34`). Each parser MUST throw a format-changed error mirroring `daily-geomagnetic-indices.ts:35` (`"no :Issued: line found — the NOAA format may have changed"`) if SWPC changes shape, so fixtures fail loudly.
- **Ultracompact Kp derivation** is a view transform, not a new product — keep it in the Home component or a tiny `deriveMinMaxKp(kpBreakdown): {day,min,max,gBadge}[]` pure helper, not a separate parser.
- **Threshold storage key** is versioned (`v1`) so future Horizon 2 cloud+HPI thresholds can migrate without clash.
- **Sequencing for implementation:** PR `1a` = scales + Kp + banner + ultracompact table + nav rename + Home reflow (all without permissions). PR `1b` = alerts filter + Notification opt-in + where-am-I pill (with mocked geolocation in tests). Keeps PRs small enough for Playwright axe to stay green per `docs/agents/coding-standards.md:36`.
- **Vocabulary:** Do not invent synonyms — use `CONTEXT.md:52` **Kp index**, `CONTEXT.md:78` **Dst index**, `CONTEXT.md:94` **Hemispheric power**, `CONTEXT.md:92` **Bz (GSM)**, storm scales as defined (`CONTEXT.md:64`). Code identifiers follow the same terms (`kpThreshold`, `bZgsm`, `hemisphericPowerGW`, `dstIndex`).
- **Re-verify CORS before coding:** Run `curl -I` against `products/noaa-scales.json:49`, `products/alerts.json:50`, `products/summary/solar-wind-mag-field.json:51`, `text/aurora-nowcast-hemi-power.txt:43`, `products/kyoto-dst.json:54` and confirm `Access-Control-Allow-Origin: *` — SWPC can change without versioning.
