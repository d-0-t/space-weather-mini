# 01: Route and geocoded place store plus daylight

**What to build:** a new top level Local conditions page at `/conditions` that is reachable from the primary nav after Webcams and shows daylight for a stored geocoded place. Opening the route with empty storage shows Kiruna, Sweden as the geocoded place without any network call, with daylight for today and tomorrow as calculated on device — sunrise, sunset, civil twilight start and end, nautical and astronomical twilight, dark window and day length — with Kiruna persisted as the last geocoded place.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] Route `/conditions` is registered as a lazy route and appears in the primary nav after Webcams with label Local conditions, with one h1 per page and the existing nav tests updated
- [x] A versioned store under `sw:local-conditions:place:v1` holds the geocoded place as display name plus lat and lon plus fetched at, reads the last place on load and falls back to Kiruna, Sweden on missing or corrupt data and writes on every pick
- [x] Daylight for the current geocoded place is derived on device with suncalc for today and tomorrow, showing sunrise, sunset, civil twilight, nautical and astronomical twilight, dark window and day length, with no network fetch for solar times and with Oslo and Kiruna fixtures pinning the suncalc call
- [x] Vitest covers the store read and write with versioning and Kiruna default and corrupt fallback, plus suncalc daylight for equinox, solstice and tomorrow shift
- [x] Typecheck, build and the existing unit suite stay green

## Comments

- **2026-09-01 – implemented (review pending).** The `write on every pick` half of the store checklist is deferred by ticket sequencing: the pick UI (search field, match list, geolocation) lands in tickets 02–03, and the `saveGeocodedPlace` seam it will call is already public and unit tested. The page writes on first open (Kiruna default stamped with the open instant).
- **2026-09-01 – timezone note.** Solar times render in the device's time zone with an explicit "in your device's time zone" label. Spec US12 wants place-local times; the geocoded place model has no timezone field, so honest v1 is device tz plus label. Place-local formatting should be decided with the weather contract (Nominatim/Open-Meteo timezone), not silently changed here.
- **2026-09-01 – solar noon and day length rows.** The ticket checklist lists sunrise, sunset, twilight intervals, dark window and day length, but the spec US9/US11 include solar noon and day length; both render. Glossary entries for Solar noon and Day length added to CONTEXT.md.
- **2026-09-01 – daylight display rework (human decision).** The time rows were replaced by a luminosity timeline: the 24 h day as duration-ratio bands (Dark window → Astronomical twilight → Nautical twilight → Civil twilight → Day), each band a palette-token color dark to bright, with the start time at each break and the band name inside. On narrow screens (≤ 480 px) the timeline flips to a vertical scale. Only Today renders for now; the Tomorrow block is kept in code (commented) and `daylightTimes` still computes tomorrow because today's Dark window ends at tomorrow's dawn. The explicit day-length number left the screen with the rows (the Day band's width carries it); revert to rows if the number is wanted back. Nautical twilight, Astronomical twilight and Day are now glossary terms in CONTEXT.md.
- **2026-09-01 – timeline polish (human decision).** The band ramp is now one desaturated blue (deep indigo lightened toward white via `color-mix`) so the bands vary in luminosity only, never hue. Wide-screen band names are rotated 180° and wrap at the band height so the longest name spans the whole band. Break times alternate top/bottom between neighbouring bands (pure CSS displacement – markup order unchanged) and e2e now pins the alternation and the rotation.
- **2026-09-01 – Night band + default place change (human decision).** The darkest band is renamed Dark window → Night (CONTEXT.md term updated; internal field names `darkWindowStart/End` kept). Presets now ship Kiruna + Luleå (`PLACE_PRESETS`); the fallback default moved to Östersund (63.18 N 14.64 E) because Luleå's sun only dips to −16° in early September, so its Night band would not have shown. This deviates from the ticket's "defaults to Kiruna" and the spec's Kiruna default; the spec/ADR stay as the historical record. The Solar noon glossary entry was dropped because the timeline replaced the rows (term no longer user-facing); Day length's entry now references the Day band.
- **2026-09-01 – timeline day-boundary bug fixed.** `daylightTimes` used to derive its day from the UTC midnight of `now`, so for UTC+2 the timeline sliced events on the wrong boundary: the Night band before astronomical dawn was dropped and the evening Night band rendered as 00:05–24:00, swallowing the day. Fix: the reference day is now the device-local calendar day of `now` (suncalc is called with the day's civil noon, because suncalc keys its event set to the nearest solar transit and local midnight can fall in the previous solar cycle). `buildTimeline` additionally clips events to the 00:00–24:00 window. Regression test pins the Östersund early-September case (Night 00:00–01:44, day ends in astronomical twilight, no past-midnight Night band); sun and conditions suites now pin `process.env.TZ` (UTC / Europe/Stockholm) to stay deterministic on any host. One l2 ramp color tweak (deep indigo/white 100/60 → 100/80) was needed because the previous l2 failed WCAG AA for its black band names (4.28:1).
