# 03: Weather for the place with WMO lookup and manual refresh

**What to build:** weather for the current geocoded place as current conditions plus a 24 hour horizontal scrolling hourly strip plus a 3 day daily row, with temp, humidity, total cloud plus low, mid and high split and a WMO weather code rendered through a local lookup to short text plus icon, refreshed only on user tap with an always enabled Refresh button and a fetched at timestamp.

**Blocked by:** 01

**Status:** done

- [x] A single Open-Meteo fetch with `current=temperature_2m,relative_humidity_2m,cloud_cover,weather_code,wind_speed_10m`, `hourly=temperature_2m,relative_humidity_2m,cloud_cover,cloud_cover_low,cloud_cover_mid,cloud_cover_high,weather_code`, `daily=weather_code,temperature_2m_max,temperature_2m_min,sunrise,sunset`, `timezone=auto`, `forecast_days=3` for the current geocoded place, mapped from raw JSON to a typed weather view model, windowed to 24 hourly entries and three daily cards
- [x] A local WMO code lookup file maps each relevant WMO code to short English text plus icon name, with a contract test that covers every used code and a safe fallback for unknown, not a geographic map widget
- [x] Current block shows temp, humidity, total cloud with a small low, mid and high breakdown and the WMO icon plus text; the hourly strip is horizontally scrollable by time and shows per hour time, temp, humidity, cloud total and low/mid/high plus WMO icon and text; the daily row shows three cards with max and min, WMO icon and text and sunrise and sunset for reference; units are Celsius and kilometres per hour only for v1 and temps and clouds come from a real Open-Meteo Kiruna fixture checked in
- [x] A Refresh button at the top of the weather card is always enabled and a timestamp reads "Data from Open-Meteo at HH:MM local" from the fetch time, clicking it reissues the same weather fetch for the same place and updates the timestamp while keeping daylight and the place visible; no polling and no refetch on focus
- [x] Loading shows a busy state, failure keeps the place and daylight visible and only swaps the weather block to a plain retryable error

## Comments

- **2026-09-01 - implemented (review pending).** Seams confirmed with the team: three tiny modules — `src/data/wmo-codes.ts` (closed WMO lookup), `src/data/weather.ts` (Open-Meteo fetch plus pure mapper) and the page component — each with its own test file. Real Open-Meteo Kiruna payload captured live 2026-09-01 and checked in at `src/data/fixtures/open-meteo-kiruna.json` (current 10.6 C, 97 %, 100 % cloud, code 63; 72 hourly entries; 3 daily).
- **2026-09-01 - current cloud split (human decision).** The `current=` contract has no low/mid/high split, so the current block borrows the split from the hourly entry of the same hour (the strip always covers the current hour). A payload whose observation falls outside the strip throws loudly rather than silently borrowing another hour, per the spec's "format change fails loudly".
- **2026-09-01 - 28 WMO codes, not 27 (spec correction).** The spec's user story 22 says "all 27 WMO codes"; Open-Meteo's docs table lists 28 (0–3, 45, 48, 51–57, 61–67, 71–77, 80–82, 85–86, 95, 96, 99). The closed map implements the full documented set and the contract test pins every one plus the fixture's used codes.
- **2026-09-01 - timestamp frame (human decision).** "Data from Open-Meteo at HH:MM local" formats the fetch instant in the device time zone — it answers "when did I fetch", not "what time is it at the place" (the strip and daily row carry the place's local times verbatim from timezone=auto). This matches the ticket's pinned copy; documented in coding-standards as the Local conditions exception.
- **2026-09-01 - TanStack Query without triggers.** The weather query sets `refetchOnWindowFocus: false` and no `refetchInterval`, with a short staleTime so the cached payload is shown between manual refreshes; a refresh failure keeps the last payload and adds "Couldn't refresh the weather – showing the last data", per the spec's in-memory cache note.
- **2026-09-01 - a11y for the scrollable regions.** Both the hourly strip and the daily table scroll on narrow screens, so both are keyboard-reachable: the strip is a named list with `tabIndex={0}` and the daily wrapper follows the daily-geomagnetic-indices `role="region"` + sr-only label pattern, keeping the axe audit green (scrollable-region-focusable).
