**What to build:** After one online visit the app opens offline. The shell precache plus last NOAA JSON and map tiles are cached; offline opens show stale data with honest `As of` plus `⚠ Showing saved data — couldn't reach NOAA` on every live card, or a plain error when never cached.

**Blocked by:** None (can start immediately)

**Status:** done

## Comments

Implemented 2026-09-03 via TDD (red→green slices), then two-axis code review. Suite green: `tsc --noEmit`, 562 Vitest, 48 Playwright (offline journeys repeated 20× green, axe audits per page).

- **PWA config** — `vite.config.ts:14` `PWA_OPTIONS` exported for the build-time seam test (`vite.config.test.ts`). The SWPC `urlPattern` is narrowed to `/services\.swpc\.noaa\.gov\/(json|text|products)/` so it cannot shadow the OVATION JPG CacheFirst route (Workbox matches routes in order, first match wins) — without the narrowing the JPGs would be StaleWhileRevalidate, defeating the ticket's CacheFirst requirement. `dist/sw.js` emits `self.skipWaiting()` + `clientsClaim()` + an SPA `NavigationRoute` fallback.
- **Offline honesty** — `src/components/pages/home/components/offline/offline.tsx`: `useIsOffline()` (navigator.onLine + events), `StaleDataNotice` (`.live-panel__warning`, `aria-live="polite"`), `FreshnessLine` (`As of {UTC} • Updated {age}`), `liveDataState(query, offline)` returning `"stale" | "never-loaded" | null`. `never-loaded` fires only on `isError && !data` so a query still loading its cached data offline never flashes the error. `SparklineCard` takes one `state?: LiveDataState` prop. All live cards (AuroraNow, Forecast, SolarWind, Magnetosphere, LiveBanner) apply it; the Kiruna magnetogram card (IRF image, not runtime-cached) honestly shows `Couldn't load – connect to refresh` when offline.
- **NetworkMode** — production QueryClient in `src/index.tsx:16` sets `networkMode: "always"`: the default `"online"` pauses queries while offline, which would leave a freshly-mounted card stuck on "Loading…" instead of the honest error. TanStack's `OnlineManager` starts online and only flips on window events, so the reload-offline journey already worked; `always` closes the SPA-navigation-while-offline hole.
- **Copy deviations (required by repo rules)** — the ticket/spec write the stale copy with an em dash `—`, but `src/test/en-dash.test.ts` bans U+2014 in code, so the shipped copy uses the en dash `–` ("Showing saved data – couldn't reach NOAA"), consistent with the pre-existing live-card copy. The ticket's `As of {Forecast Time}` is approximated on the pre-canvas cards with the observation `time_tag`; the OVATION `Forecast Time` lands with the canvas (ticket 04).
- **Test seams** — `e2e/offline.spec.ts`: (1) build emits `sw.js`+`workbox-*`; (2) online visit → offline reload → h1 + `As of` + `⚠`; (3) axe audit of the offline stale view; (4) shell installed via `/about` (no data ever fetched) → offline → plain error, no invented data. Playwright's `setOffline` does not flip `navigator.onLine` on SW-served pages and cannot force the SW's own runtime fetches to fail, so the tests use a page init script to emulate the true offline state (navigator.onLine=false + offline event) and a fetch-rejection seam for the never-cached case. The live cache is warmed deterministically by writing the responses into the `swpc` cache directly.
- **Pre-existing fix (drive-by)** — `PlaceFinder.tsx` imported `{ OpenInNew }` from the `@mui/icons-material` barrel, which made the lazy `/conditions` chunk hang in Vitest (its import graph never resolved) and broke `app-shell.test.tsx`; switched to the direct path import used everywhere else. Also `src/setupTests.js` now resets TanStack Query's `OnlineManager` singleton after each test (a test that fires `offline` otherwise leaves every later query in the file paused).
