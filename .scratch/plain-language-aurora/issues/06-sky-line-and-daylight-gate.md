Design decisions as built: the Night gate is `dark-now` / `daylight` / `polar-day`, and `lookNow` is true only in `dark-now` (N8). The daylight/polar-day line states the coming dark window and a "look now" claim never appears. Cloud is two honest bands - under 50% reads "fairly clear", 50%+ reads the percent plus "may hide the aurora"; a missing weather feed reads "Cloud cover isn't available right now" (N10: never a guessed value). The Moon modifier rides only a `dark-now` line and only while the Moon's center is above the horizon (`isMoonAboveHorizon`, ticket 02) - a Moon below the horizon never vetoes a night (N7); when position is unknown the clause is omitted. Reach uses the View distance band + confidence (`viewDistanceBand` lookup, new shared accessor in `products/view-distance.ts`) and always carries its 30-90 minute lead time, the approximate-averages and geomagnetic-not-geographic caveats, and no city strings (N3/N5/N11). The visibility caveat ("may be seen", "unlikely, though not impossible") rides only a `dark-now` line; in daylight the same forecast is stated as a fact about where the glow is, so the line can never read both "aurora isn't visible" and "it may be seen". The component holds until the shared weather query and the Oval grid query have settled; both reuse the existing query keys (weather via the new `useWeather` hook shared with `CurrentWeatherLine`), so each feed is still fetched once. Cloud fetched-at renders in the Display timezone (`formatClock`).

Follow-ups / residual risks (deliberately not smuggled into copy): (1) N10 residual - OVATION can fall back to a Kp-driven estimate with no forecast lead time, but `OvationProduct` carries no fallback flag, so the standard 30-90 minute lead is stated and the gap is recorded here rather than guessed; `OvalGlow`/`ViewDistanceLine` already state the same lead unconditionally. (2) The Moon half is the instant gate at `now` (the confirmed seam), not an overlap of the Moon's up interval with the whole dark window - honest as a look-now line, and `moonTimes` window data remains unused here. (3) "Tips phrasing for reach" is satisfied at the Kp interval rows (ticket 03); the sky line's place-based reach is the View distance band, which is the correct vocabulary for a distance-to-oval line and carries the same averages/geomagnetic caveats. Vocabulary graduated into `CONTEXT.md`: Sky line, Daylight gate; the Interpreter definition now names the Sky line.
